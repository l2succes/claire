01 · Product outcome

Make the next important move obvious.

Open Loops should feel like a calm, human chief of staff: surface the few commitments worth attention, preserve the source conversation, make uncertainty explicit, and let the person teach Claire what matters.

Trusted

Every loop links to evidence and says why it is here. Claire never pretends inference is fact.

Finite

The home surface has an attention budget. A list may contain 197 open loops; today should usually show 3–7.

Correctable

People can pin, reprioritize, mute, fix ownership, or say “not a loop” in one tap.

Core rule: notifications deliver a decision already made by the priority system. They must not be the place where an expensive or opaque background model decides what a person should care about.
02 · What a loop means

Separate the request from the responsibility.

The birthday example exposes the missing distinction: “who asked?” and “who owes the next move?” are related, but not interchangeable.

RequesterWho initiated or asked for the outcome.
OwnerWho owes the next action.
CounterpartyWho is affected or expected to respond.
StateHow settled the plan is.

Required schema change: persist requester and requester identity separately from owner. The detail card should say “You asked Maya for help · waiting on Maya,” not force people to infer this from an unreliable participant label.
03 · Priority algorithm

Score facts, not vibes.

The extractor identifies structured facts from a bounded conversation window. Deterministic code calculates priority whenever a message, deadline, loop state, or preference changes. No continual LLM pass is needed.

priority = urgency + responsibility + commitment + relationship + freshness + user intent − quieting penalties
Clamp to 0–100. Store component scores so “why this is high priority” is always explainable.
ComponentRangeExamplesWhy it matters
Deadline urgency0–30Overdue 30; today 27; next 3 days 20; next week 10.Time-sensitive promises must rise without an LLM deciding that every date is urgent.
Responsibility0–15You owe next 15; shared 10; waiting on them 7; unassigned 0.Moves the user can make deserve more attention than passive observations.
Commitment strength0–12Agreed/explicit 12; pending confirmation 8; negotiating 3; proposed 0.A firm commitment beats a vague future possibility.
Relationship & scope0–12Pinned person/project, repeated thread, high-value group, direct ask.Lets Claire respect context without inventing a social hierarchy.
Freshness & aging0–8New evidence, an unanswered follow-up, or a loop quietly aging past its expected window.Prevents both forgotten commitments and constant resurfacing.
User intent0–25Pin +25; focus topic/person +12; manual importance +10; “more like this” +5.The user’s explicit preferences outrank all inference.
Penalties / exclusion0 to −∞Snoozed, muted chat, low confidence, resolved, duplicate, proposal-only, stale offer.Noise should leave the attention queue rather than merely sorting lower.

Priority bands

80–100 · Act now Time-sensitive and meaningful. Eligible for a timely notification.

55–79 · Today / this week Belongs in the daily focus queue or a calm digest.

30–54 · Keep visible In the full list, but not interruptive.

0–29 · Quiet Searchable/history state; surface only with a matching user preference or new evidence.

Preference controls

Pin a loop; choose focus people, projects, and topics; mute a chat or loop type; set manual importance; and calibrate with “more like this” / “less like this.”

Each control writes a durable preference or loop override. It is not a hidden one-off prompt and can always be reviewed or undone.

04 · Filter signal from noise

Not every conversational possibility deserves a task.

A high-value relationship or pinned project waiting on a response.Open-ended social offers, promotions, rentals, and FYIs.Store low-confidence candidates quietly if useful for search; do not page the user.

Default attention budget: show at most five “Act now” items and up to seven “Today / this week” items on Home. When more qualify, choose the highest score and say “12 more in Loops,” rather than turning the home screen into a backlog.
05 · Redesigned Loop cards

Quiet rows, hard separators, one clear next move.

The current card has too much narrative and inconsistent height. The new list is a simple sequence of rows: concise title, one supporting line, conversational context, and a deadline. The detail view contains the evidence and long narrative.

Rows use a single border separator rather than floating cards. Color is reserved for an actionable state, never decoration.

Row anatomy

Completion control · 1–2 line title · one-line context · ownership/state chips · date. No full detector narrative in the list.

Sorting

Primary: priority score. Tie-breakers: overdue deadline, user pin, newest evidence. “Waiting on them” is a filter, not a lower-quality loop.

Detail view

Show “You asked Maya; Maya owes the next move,” evidence, history, snooze, correction controls, and an action such as draft nudge.

Other app surfaces

  • Conversation header: a compact “1 open loop” affordance, never a large interruption.
  • Chat timeline: evidence markers on the original messages; a loop detail opens on tap.
  • Search: loops rank alongside messages and people, using concise title plus conversation name.
  • People / project views: optional “active commitments” section, scoped by the same priority model.

What never duplicates

  • Home does not show every open loop.
  • Notifications do not repeat the Home queue unless priority crossed a new threshold.
  • The chat shows source context, not another task manager.
  • Loops remains the durable workspace for full inventory, filtering, corrections, and history.
07 · Conversation context

Show the loop where the conversation happens.

A loop should be visible in the Inbox and inside its source chat, but never turn the message thread into a second task manager. The chat presents the context; Loop Detail owns edits, snoozes, and resolution.

08 · Delivery policy

Be helpful without becoming another inbox.

Event-driven scoring

Recalculate when a relevant message arrives, a deadline/snooze boundary passes, a loop is edited, or the user changes a preference. This is ordinary database/application work, not a recurring model task.

Digest and push rules

Push only for a new 80+ score, a due/overdue commitment the user owns, or an explicit reminder. Otherwise place it in the next local-time digest within the attention budget.

SituationDeliveryExample
Score crosses 80 and user owes actionImmediate, rate-limited push“Demo to investor is overdue.”
Waiting on someone, follow-up window just openedDigest or quiet Home card“Maya has not confirmed birthday plans.”
Low-confidence or proposal-onlyNo push; quiet list or confirm prompt“Possible coffee next week.”
Snoozed, muted, completed, or low scoreNo deliveryOnly visible by browsing/searching.
