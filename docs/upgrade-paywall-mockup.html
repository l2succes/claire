Why this timing works

The user has already invested effort by connecting accounts and has seen proof that Claire can access their real conversation graph. The value proposition is specific: organize recent history, rank it, and surface it in context.

No surprise charge The primary action opens a clear plan sheet. The secondary action keeps the free product usable and lets feature gates sell Pro again at the point of need.

Implementation contract

Claire creates a Stripe Checkout Session for the authenticated user, carrying the Claire user ID as a stable metadata reference. A verified webhook activates Pro; the app reads only the resulting entitlement state, never trusts a client-side payment return.

Suggested placeholder $12/month is visual-only in this mockup. The shipping price must come from a configured Stripe Price ID, not this document.

04 · Behavior contract

Make the upgrade state dependable.

1. ConnectUser connects at least one account during onboarding.
2. DiscoverClaire shows the Pro outcome: organize recent conversation history.
3. CheckoutClient requests a session; Stripe hosts payment and confirmation.
4. EntitleVerified Stripe webhook records an active Pro entitlement.
5. DeliverServer queues the bounded history scan; the app refreshes loops when it completes.
Important sequencing: payment success is not the signal to run a client-side scan. The webhook-entitlement transition queues server work exactly once, making retries, upgrades, cancellations, and account changes auditable and idempotent.
